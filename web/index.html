DOCS // MANUAL

Reverse.Local User Guide & Architecture Manual

Complete reference for Domain Routing, Native Go SSH Tunneling (-L -N), LAN DNS Broadcast, Persistence & OS Installers.

Automatic Administrator Elevation

When you double-click reverse-local.exe, it automatically requests Run as Administrator privileges so it can bind ports 80 and 443, synchronize your OS hosts file, and register the local Root CA.

STEP 1 // TRUST ROOT CA

On first launch, Reverse.Local generates a 10-year RSA-2048 Root CA and installs it in your OS trust store. You can also click Trust CA or download /ca.crt from the top bar.

STEP 2 // MAP A DOMAIN

In [01] Domain Routing Matrix, enter a domain (e.g. api.project.local) and your local port (e.g. http://127.0.0.1:3000), then click Bind Route.

STEP 3 // OPEN HTTPS URL

Visit https://api.project.local in any browser. Reverse.Local signs an on-the-fly TLS certificate via SNI and proxies HTTP & WebSocket traffic.

How Automatic Hosts Synchronization Works

Every active domain is written inside an isolated block (# BEGIN LOCAL-REVERSE-PROXY ... # END LOCAL-REVERSE-PROXY) in C:\Windows\System32\drivers\etc\hosts (Windows) or /etc/hosts (macOS/Linux). Your custom manual host entries outside this block are never modified.

Built-In Pure Go SSH Local Port Forwarding (ssh -L -N)

No external PuTTY or OpenSSH CLI process is required. Reverse.Local uses golang.org/x/crypto/ssh to dial your remote jump host, keep the connection alive, auto-reconnect on network drops, and forward local ports to remote private services.

1. Create an SSH Tunnel Profile

In [01B] Native Go SSH Port Forwarding (-L -N), click + New SSH Tunnel and provide:

  • SSH Server: user@bastion.example.com:22
  • Local Bind Port: e.g. 127.0.0.1:15432 or 127.0.0.1:18080
  • Remote Target Host & Port: e.g. 10.0.0.12:8080 (reachable from the SSH server)
  • Authentication: Private Key (~/.ssh/id_ed25519), Password, or OS SSH Agent.
2. Bind a Local HTTPS Domain to an SSH Tunnel in 1 Click

Once a tunnel is created, click Bind Domain on the tunnel card. It pre-fills http://127.0.0.1:<local_port> in the Domain Route editor so you can access a remote staging API via https://staging-api.local with full HTTPS and live traffic inspection.

MODE A // ZERO-CONFIG mDNS (UDP :5353)

Automatic for .local Domains

Reverse.Local includes a built-in Multicast DNS (224.0.0.251:5353) responder. When you set Bind Interface to 0.0.0.0, any Windows, macOS, iOS, or Linux device on the same Wi-Fi automatically resolves https://<name>.local to your LAN IP without changing DNS settings.

Note: For subdomain routes (e.g. api.app.local) or Android devices, use Mode B (LAN DNS Server) below.

MODE B // LAN DNS SERVER (UDP :53)

Works for All Devices & Any Domain (.local, .test, .dev)

Reverse.Local also runs a lightweight UDP Port 53 DNS responder. Point your phone, other PC, or Wi-Fi router's Primary DNS Server to 192.168.x.x:

  • Queries for your active routes return your LAN IP
  • All other internet queries are transparently forwarded to 8.8.8.8 / 1.1.1.1.
Trusting HTTPS Certificates on Other LAN Devices

On the other computer or phone, open http://192.168.x.x/ca.crt to download and install the Reverse.Local Root CA certificate. Leaf certificates automatically include your LAN IPv4 address in their SANs.

Automatic Disk Persistence

Every domain route, SSH tunnel profile, and daemon setting you create is immediately saved to disk using atomic file writes (temp-file + rename) in your OS configuration directory:

Directory: %AppData%\reverse-local
Domain Routes: routes.json
SSH Tunnel Profiles (-L -N): tunnels.json
Daemon & Network Settings: settings.json
Root CA Keypair: certs/ca.crt & certs/ca.key

[WINDOWS] Native .MSI Installer

Ready-to-run package in dist/ReverseLocal-1.2.0-x64.msi:

  • Direct Windows Installer (.msi) built via native msi.dll & makecab.exe (installer/windows/build-msi.ps1 & WiX Product.wxs).

  • Creates Desktop & Start Menu shortcuts (`Reverse.Local`).
  • Also includes install-windows.bat for 1-click Firewall + UAC setup.
